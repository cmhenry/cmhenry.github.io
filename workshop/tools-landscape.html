The landscape

Overlapping ways to use a model

  • Chat applications — conversation, sometimes with files and tools.
  • Harnesses — a terminal where the model can read and write your files.
  • Agent workflows — repeated tool use, sometimes scheduled or delegated.
  • An API connects software to a model or service. It does not supply a workflow by itself.
What actually differs

Three axes

  • Autonomy — how many steps it takes without you.
  • Access — what it can read, write, and run.
  • Latency — seconds, minutes, or hours to a result.
  • Choose the access and supervision the task requires.

Desktop apps

Conversations, uploaded files, and connected tools.
Chat + Projects

The familiar one

  • Conversation is the main interface; file and tool access depend on the product.
  • Projects add persistent instructions and a small file store.
  • Good for: drafting, brainstorming, one-off questions, reading a PDF you pasted in.
  • Check memory, connectors, and permissions rather than assuming the chat is isolated.
Cowork

Chat, plus your folder

  • Same chat interface — but pointed at a folder on your disk.
  • The model can read, write, and edit files there. It runs code in a sandbox.
  • Connectors can add service access; availability and permissions vary.
  • Good for: anything where the answer is a file, not a message.
  • The presenter shows the permissions in the prepared demonstration environment.
Scheduled · Dispatch

Scheduled and background work

  • Scheduled tasks — run a prompt on a cron. "Every Monday, summarize my inbox."
  • Dispatch — fire off a long job in the background, come back to the result.
  • Availability depends on the application, account, and execution environment.
  • Specify scope, output, failure reporting, and how to pause the job.

Harnesses

The model, in your terminal, with your tools.
What's a harness?

A loop, not a chat

  • A CLI program that runs an agentic loop: think → act → observe → repeat.
  • "Act" means: edit files, run shells, call APIs, search the web.
  • You watch the loop. You can interrupt, redirect, or approve each step.
  • Born for coding, but works for any task that lives in files.
Claude Code

Anthropic's harness

  • Terminal app. Lives in a directory. Reads and writes its files.
  • Tools: bash, file edits, web fetch, subagents, MCP connectors, skills.
  • You can stop it, branch it, run several in parallel on different worktrees.
  • Inspect the actual file changes, tool calls, and approval settings.
Codex

OpenAI's harness

  • Same shape as Claude Code: terminal, files, agentic loop.
  • Powered by OpenAI's models. Different defaults, different feel.
  • Useful when you want a second opinion from a different model family.
  • Reusable instructions may transfer; tool names and permissions need checking.
Open source harnesses

aider, opencode, and Cline

  • Open-source command-line or editor interfaces with different supported backends.
  • Some can use hosted APIs or locally served open-weight models.
  • Local inference can change cost and data handling; inspect the complete setup.
  • Local operation alone does not establish confidentiality or reproducibility.

Agentic systems

Delegated tasks with explicit limits and review.
What's an agentic system?

Repeated actions toward a goal

  • A harness can also run agent workflows, locally or on a remote host.
  • The system selects tools and uses their results to choose subsequent actions.
  • Supervision can include approval checkpoints, budgets, and stopping rules.
  • Review the execution record as well as the final answer.
Inspect a prepared workflow

What was actually delegated?

  • Show one bounded task in the presenter's configured agent environment.
  • Identify permitted inputs, tools, output location, and stopping condition.
  • Open its run history and show how the task can be stopped.
  • A saved run is an inspection exercise, not a live execution.
When to reach for one

The task fits the shape

  • Multi-hour work you've fully scoped (not exploration).
  • Steps with clear permissions, stopping conditions, and failure reporting.
  • You can verify the output afterwards without re-doing the work.
  • Bad fit: anything where the right answer requires your judgement mid-flight.
Picking one

Match the tool to the task

  • Thinking with words? Chat window.
  • Producing a file? An interface with appropriate file access.
  • Editing a codebase or running scripts? A harness.
  • Recurring or scheduled? Scheduled tasks.
  • Long-horizon, fully delegated? An agentic system.
