The task

What is the output for?

  • Drafting a question: preserve the intended construct.
  • Coding responses: compare labels against a defined codebook and human judgments.
  • Simulating respondents: distinguish software tests from population inference.

25 minutes · Complete inputs and copyable requests · no installation required

Question wording

Which question measures the construct?

Target: researchers’ views on sending de-identified interview transcripts to a commercial AI service for analysis.

  • A: “Should researchers stop using unreliable AI tools that threaten privacy?”
  • B: “How acceptable is AI use in academic research?”

Before using a model, identify leading language and changes in what is being measured.

Question wording

A revision still needs testing

  • Write one item and response scale for the stated construct.
  • Ask a model to critique the items using the complete request in the practical.
  • Check what the revision preserves, removes, or adds.
  • Propose a cognitive-interview probe for real participants.

Readable wording is evidence of face plausibility, not proof of validity. Model role-play does not replace human pretesting.

Coding responses

Fix the codebook before coding

  • P: privacy, disclosure, or third-party access.
  • V: accuracy, evidence, or ability to verify.
  • E: unequal resources or representation.
  • O: other/unclear; never combine with P, V, or E.

Use explicit text. Multiple substantive labels are allowed. Record human judgments before model output.

Constructed teaching responses

Code all three responses

  • A: “I do not want interviews sent to a vendor, even after names are removed.”
  • B: “The references look convincing; how do I know they are real?”
  • C: “Better-funded colleagues buy better tools; we cannot check every translation.”

Return a label and exact supporting text. These are constructed examples, not real survey data.

Checking the coding

Inspect disagreements

  • Compare each model label with the initial human label and quoted evidence.
  • Separate a coding error from a codebook ambiguity.
  • Record any codebook revision and apply it to all cases.
  • For a study: use held-out human coding, adjudication, and relevant language/subgroup checks.

Agreement on three constructed cases cannot validate the measure or estimate deployment accuracy.

Synthetic respondents

Two uses, different claims

  • Proposal A: generate answers to fill an underrepresented subgroup, then analyze them as human responses.
  • Proposal B: generate marked cases to test skip logic, file formats, and analysis code.

What is observed in each case? What human evidence would the claimed inference require?

Limits of simulation

Plausible answers are not a sample

  • A software test can reveal a broken branch without estimating a population attitude.
  • Matching answer percentages does not establish relationships among answers.
  • Subgroup comparisons and causal claims require their relevant validation evidence.
  • Keep generated and human observations distinguishable.
Apply to a project

Specify one use and one check

  • Where could an AI-assisted task enter your research?
  • What comparison would show whether the output is useful?
  • Which inference still requires human evidence?
