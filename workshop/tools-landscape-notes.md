# Tools — presenter notes

Target: 15–18 minutes. Preserve time for the research tasks. Product capabilities depend on version, account, permissions, and configuration; verify the presenter environment before teaching.

## Slides 1–3: compare capabilities

Chat applications, harnesses, and agent workflows overlap. A terminal does not imply supervision and a hosted service does not imply autonomy. An API is a programmatic interface, not an agent. Compare access, permitted actions, supervision, and time to a result.

## Slides 4–7: conversation and files

Show an ordinary chat with a public teaching input. Identify retrieval, attached files, memory, or connectors actually available. Do not disable tools to make this route look inadequate.

For the file-working example, use a prepared directory containing only public teaching material. Show the directory boundary and one permitted file read. Do not assume a product supports every connector or that a sandbox settles confidentiality.

Explain scheduled versus background work using an existing prepared example. Identify the output location, failure behavior, and pause control. Do not activate a new recurring job during the workshop without a separate decision.

## Slides 8–12: harnesses

Show a prepared Claude Code, Codex, or equivalent session. A useful request is: “Read this teaching file and list its headings. Do not edit files, install packages, or contact external services.” Show the actual operation and output.

Participants do not install a harness. Observing this demonstration teaches inspection, not installation competence. If the environment fails, discuss the request and permission boundary; label this as inspection rather than successful execution.

Open-source software and local model inference are separate choices. Local inference may reduce some disclosures, but logs, connectors, backups, access controls, and research governance still matter. Cross-model agreement is comparison evidence, not independent verification.

## Slides 13–16: delegated work

Show one existing bounded task and its execution history in the prepared agent environment. Point to its input, authorized actions, stopping condition, and saved result. A saved run must retain its date and status. Do not describe a prerecorded run as live.

A suitable workflow may run locally or remotely, with approval checkpoints. If a research decision cannot be specified in advance, retain a human checkpoint rather than delegating it implicitly.

## Slides 17–18: select a route

Use the least access needed for the task. The practicals support an available chatbot, the instructor's retrieval environment, or manual inspection. No paid model account or new installation is required for inspection. Explain which capabilities a participant did and did not exercise.
