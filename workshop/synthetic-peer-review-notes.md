# Synthetic peer review — presenter notes

Target: 25–30 minutes. Use `peer-review-practical.md` for the complete shared input and requests. This is a pre-read exercise, not journal review or a validated instrument.

## Preparation and baseline (slides 1–4)

Use the labeled constructed excerpt or a public/permitted draft. Do not upload confidential peer-review manuscripts or coauthor material without permission. Participants record their assessment before model output.

Hold the model, tools, excerpt, and available context fixed. Start a fresh conversation for each pass and save exact requests and responses. Run the ordinary prompt first. It may produce a strong critique; no failure is required.

## Rubric and specialization (slides 5–8)

Use the complete rubric request in the practical. The slide's short skill is an illustration, not a functioning installation. Chat-only users can paste the instructions. Check product-specific installation separately in the presenter environment.

Require a quoted passage, explanation, severity, and limitation for each criticism. Do not demand causal identification for a purely descriptive claim just because a methods template has that heading. Distinguish a flaw in the stated inference from a proposal for a different study.

Specialization changes the procedure; it is not evidence of improved accuracy. The credited external examples are optional reading, not required downloads or tested dependencies.

## Coordination and severity (slides 9–10)

Automatic dispatch requires actual subagent support. Without it, run two fresh chats and compare manually. Fresh contexts reduce direct anchoring but do not establish statistical independence. Shared training, prompts, and inputs can generate shared errors.

Agreement is a reason to inspect evidence, not a confidence score. A severity rule written in prose is not executable enforcement. Retain, reject, or mark a concern unresolved after checking the text.

## Evaluation and transfer (slides 11–14)

Compare supported concerns, unsupported concerns, and missed issues against the human assessment. The constructed case makes judgments inspectable; it does not provide an error-rate estimate. Famous flawed papers can be recognized from training, so identifying a known scandal is a weak test of critique ability.

Do not tune instructions and assess performance on exactly the same excerpt. Use a fresh case for a later check. Rejecting an unsupported model criticism is as valuable as making a warranted revision.

## Model unavailable

Use the constructed review statements supplied in the practical. They are not recorded model responses. Participants can still decide which criticisms are grounded and what evidence is missing. Do not report this as a live model comparison.
