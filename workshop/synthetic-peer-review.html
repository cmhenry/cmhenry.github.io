The task

Reviewer Two, on demand

  • You have a draft. You want a structured critique before you present it or send it to a journal.
  • We'll build a skill — a reusable file Claude loads on demand — to do exactly that.
Pass 0 — Just ask

The naive prompt

Open Claude Desktop, attach your draft, type:

Review this paper and tell me what's wrong with it.
Likely response

The praise sandwich

  • Sycophancy: "This is a thoughtful contribution to the literature."
  • Vague critique: "Consider clarifying the framing."
  • No teeth: No identification critique, no causal-language audit.

Remember, RLHF rewards sounding helpful. Helpful ≠ rigorous.

What a skill is

A reusable recipe

  • A markdown file with YAML frontmatter.
  • name + description tell Claude when to load it.
  • The body tells Claude how to do the job — role, steps, output format.
  • Lives in ~/.claude/skills/ (or your project folder).
---
name: peer-review
description: Critique an
  academic draft as a
  meticulous referee.
  Use when the user
  shares a paper and
  asks for review.
---

# Peer Review

You are a meticulous
referee for a top journal.

## Steps
1. Identify the claim.
2. Audit the design.
3. Score Red/Yellow/Green.
4. Verdict: ACCEPT,
   REVISE, or REJECT.
~/.claude/skills/peer-review/SKILL.md
Installing a skill

Three ways in Claude Desktop

  • Write one with Claude: describe the job, let Claude scaffold the SKILL.md.
  • Upload: drop a SKILL.md or .skill bundle into Settings → Capabilities → Skills.
  • Browse: install from the built-in Skill Library.

Reference: claude.com/docs/skills/how-to

Pass 1 — A reviewer skill

Give it a role and a rubric

Using the peer-review skill, critique the attached draft.

What changes

  • Structure: sections, dimensions, severity scores.
  • Specificity: findings tied to passages, not impressions.
  • Limit: still one generalist reviewer covering methods and prose.
Pass 2 — Specialize

Two reviewers, two files

  • Methodology skill: identification, causal language, robustness.
  • Writing skill: argument structure, clarity, voice.
  • Shorter files are easier to audit, edit, and version.
  • Two specialists tend to outperform one generalist prompt.

Pass 3 — Orchestrate

One skill that dispatches both

  • A top-level peer-review skill runs both critics in parallel.
  • Each runs in a fresh context, so judgments stay independent.
  • The orchestrator synthesizes agreements, disagreements, and unique findings.
  • Adding a third critic later (theory, policy) is cheap.
# Peer Review (orchestrator)

## Step 1: Read draft
Read the file user shared.

## Step 2: Dispatch (parallel)
- Task: review-methodology
- Task: review-writing

## Step 3: Synthesize
- Agreements (highest
  confidence findings)
- Disagreements (surface,
  don't pick a winner)
- Unique per-critic
  insight

## Step 4: Verdict
ACCEPT / REVISE / REJECT
with Red/Yellow/Green
breakdown.
peer-review/SKILL.md — the conductor
Build a quality gate

A verdict the skill can refuse

  • Severity: each finding gets 🔴 Red, 🟡 Yellow, or 🟢 Green.
  • Rule: any Red → REVISE. Hard-coded in the skill text.
  • Effect: removes the praise-sandwich escape hatch.
Evaluate the evaluator

Validate it like an instrument

  • Run it on a paper you know well: your own work, or a famously flawed paper.
  • Compare its findings to what a human referee caught.
  • Two failure modes: false Reds (paranoia), missed Reds (sycophancy).
  • Edit the skill until the rate of both drops.
Reading the four passes

What each pass adds

  • Pass 0: flattery, no rigor.
  • Pass 1 (skill): role and rubric. One generalist.
  • Pass 2 (+ specialists): methods and prose reviewed separately.
  • Pass 3 (+ orchestrator + gate): synthesis and a verdict.
Takeaways

What we built

  • A skill is a reusable, editable markdown file: role, steps, output, gate.
  • Smaller composed skills are easier to maintain than one large prompt.
  • A verdict gate is what prevents drift back to flattery.
  • Same pattern applies to grant pre-reads, response-to-reviewers, conference abstracts.
