# cmhenry.github.io

A small HTML/CSS academic site inspired by [Ben Recht's homepage](https://people.eecs.berkeley.edu/~brecht/index.html): a dark left navigation, a small portrait, short biography, and plain text-led pages. On phones, navigation moves above the content. No JavaScript, external fonts, or new framework is required.

## Edit and build

The existing `data/*.yaml` files remain the source for publications, projects, contact information, and profile links. Page layout lives in `templates/*.html.jinja`; the redesign uses only `styles/academic.css`. The homepage biography and teaching descriptions live in their templates.

```sh
# Create an isolated build environment (Python, Jinja2, and PyYAML).
uv venv .venv
uv pip install --python .venv/bin/python -r requirements-test.txt
.venv/bin/python build.py
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m unittest discover -s tests -v
```

Commit the generated `index.html`, `publications.html`, `projects.html`, `teaching.html`, and `contact.html` along with template/data edits: GitHub Pages serves checked-in HTML, not the Python build.

The course, workshop, dissertation page, PDFs, and legacy styles are retained. Only the personal-site pages use the new stylesheet. Older homepage section fragments remain as small links to the corresponding new pages.

## Delivery boundary

This design is developed in isolated feature branches. The existing Pages workflow deploys only `main`; pushing a feature branch does not deploy it. Merge/deployment remains a separate decision.

## Course pages

The overview, nine module pages, and shared resources at `course/ai-research-tool/` are standalone, editable HTML. They share `styles/academic.css` with the personal site and use `styles/course.css` for code blocks, exercises, and the collapsible mobile course menu. They are not regenerated by `build.py`.

The test fixture `tests/fixtures/course-inventory.json` records the pre-restyle teaching text, code blocks, answer-key counts, links, and section IDs. The preservation check protects this presentation-only conversion; update the fixture deliberately when approving future teaching-content changes. Beautiful Soup is a test dependency only, not a site/build dependency. Optional browser acceptance uses `websockets` and a separately started task-owned Chromium on a loopback CDP port. Start a temporary loopback HTTP server in a separate terminal (directory links must be tested over HTTP, not `file://`):

```sh
python3 -m http.server 8766 --bind 127.0.0.1
```

Then run the browser checks, and stop the temporary browser/server afterward:

```sh
python tests/browser_acceptance.py --port 9234 --include-course --base-url http://127.0.0.1:8766/
```
